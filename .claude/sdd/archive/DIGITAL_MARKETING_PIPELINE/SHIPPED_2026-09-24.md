## Summary

A production-grade, deterministic ELT pipeline for digital-marketing data on GCP — simulated GA4, Google Ads, and YouTube sources flow through GCS → BigQuery → dbt marts, orchestrated by Astronomer Airflow with Astronomer Cosmos, gated by dual data-quality layers (dbt tests for model structural integrity + Great Expectations for data health). Built as a self-directed portfolio project with full SDD traceability (BRAINSTORM → DEFINE → DESIGN → BUILD → SHIP), idempotent incremental architecture, and documentation sufficient to explain end-to-end in a job interview.

## Lessons Learned

### Process

- **Parallel specialist delegation with a shared contract eliminates integration surprises** — The 62-file manifest with explicit agent assignments and KB-grounded patterns allowed 8 specialists to work in parallel (2 waves) without merge conflicts. The cross-contract alignment fix (datagen output dirs ↔ loader `TABLE_BY_GCS_DIR`) was caught early because both sides had explicit, documented contracts in the DESIGN.
- **Single-session SDD execution is viable when the PRD is mature** — The PRD provided 90% of DEFINE content; the clarity gate caught the `digital_marketin`/`digital_marketing` dataset name contradiction immediately. For well-scoped portfolio projects, the full 5-phase cycle can compress to one session without losing traceability.
- **YAGNI park with recorded reasons prevents scope creep** — 13 items explicitly deferred (CSV export, GCS Data Docs, SCD2, CI, etc.) kept M0–M6 tight. Each has a "Can Add Later?" column in BRAINSTORM, making the trade-off visible and reversible.

### Technical

- **`insert_overwrite` + 3-day lookback is the correct BigQuery incremental pattern** — KB `dbt/incremental-strategies.md` (0.95 confidence) confirmed: `merge` on unique_key is slower and doesn't cleanly overwrite re-runs. The 3-day lookback absorbs late-arriving rows without full scans. No `unique_key` on incremental facts — grain uniqueness enforced by dbt `unique` tests instead.
- **Deterministic RNG per `(seed, date, source)` via SHA-256 is essential for backfill≡daily equivalence** — The legacy generator's shared RNG stream (defect D6) caused cross-source coupling. SHA-256 of `f"{seed}:{date}:{source}"` guarantees independence and cross-run reproducibility without builtin `hash()` (which has per-process salt in Python 3.14+).
- **GCS flat layout `raw/<gcs_table>/dt=...` beats PRD's nested layout for loader simplicity** — The loader's `TABLE_BY_GCS_DIR` maps short table dirs → BigQuery table names. One-line `gcs_prefix` change to revert; documented in both config.py and decisions.md.
- **GX Core 1.x in a dedicated venv is non-negotiable for Airflow compatibility** — GX 0.18 is retired; 1.x API changed significantly. The dedicated venv isolates pandas/pyarrow version conflicts from datagen and dbt. The runner uses query assets with explicit partition-scoped SQL to avoid GX's batch SQL generation edge cases.

### Communication

- **Resolving the PRD's `digital_marketin` typo in Phase 0 saved rework in Phase 2/3** — BRAINSTORM Q1 forced the decision before DEFINE locked it in. The typo appeared in 3 PRD sections; fixing it once in DEFINE propagated to DESIGN, dbt profiles, and bootstrap.
- **Explicitly separating "what the code does" (docs) from "why we chose it" (decisions.md) helps interview readiness** — The README summarizes; decisions.md records context/decision/why for each ADR; data_dictionary.md is the exhaustive column reference. This three-tier structure matches the portfolio goal G5.

### Tools & Libraries

- **Astronomer Cosmos `DbtTaskGroup` with `ExecutionMode.LOCAL` + `dbt_executable_path` is the simplest reliable integration** — Virtualenv-per-model (`VIRTUALENV` mode) adds overhead; `LOCAL` with a pinned dbt venv works on Astro Runtime 3.2-8. Fallback to shell `dbt` command documented for M5 verification.
- **`sqlglot` for BigQuery SQL parsing in CI is a lightweight alternative to `sqlfluff`** — The dbt specialist used `sqlglot` to validate all 18 rendered models against BigQuery dialect in the build environment (no dbt install needed). 0 errors caught several syntax issues early.
- **`numpy.random.SeedSequence` / SHA-256 for deterministic RNG is future-proof vs builtin `hash()`** — Python 3.14's per-process hash salt breaks cross-run determinism if you use `hash()`. Explicit cryptographic hash avoids this entirely.
